# 삽화 검수·커밋 지침 (Claude Code)

Codex가 `tools/WORK.md` 대로 그려 `img/` 에 넣은 그림을 Claude Code가 살펴보고, 맞는 것만 커밋해 `main` 에 올린다.
Orca 자동화가 매시 10분(그리기 사이) `uv run tools/auto.py can-review` 가 0일 때(검수할 그림이 있고 그리는 중이 아님) 맡긴다.

## 할 일

1. `git status --porcelain -- img` 로 새로 생기거나 바뀐 `img/**/*.webp` 를 모은다.
2. 그림마다 (`<id>.webp` = 도판, `<id>.id.webp` = 동정 도해):
   - 그림을 열어 본다.
   - 정답과 대조한다: `uv run tools/illustrate.py prompt <id>` 의 프롬프트(art.* 묘사, `Mistakes to avoid`),
     `art/ref/photos/<id>/` 의 실제 사진 가운데 새가 또렷한 것 1–2장.
   - **떨어뜨리는 기준**은 `tools/WORK.md` 3단계의 '한눈에 보이는 큰 잘못'과 같다
     (다른 종·다른 철처럼 보이는 색과 무늬, 없는 댕기, 부리·몸 비율, `Mistakes to avoid`, 글자·서명·테두리, 부자연스러운 자세, plate인데 배경 풍경·모습 수 틀림).
     작은 차이로는 떨어뜨리지 않는다.
   - 눈대중으로 넘기기 쉬워 따로 확인한다(전에 통과시켰다가 사람이 떨어뜨린 것):
     - **부리 길이**: 부리 기부에서 끝까지를 머리(부리 기부에서 뒷머리까지)에 견주어 몇 배인지 재고, 사진 속 같은 종과 비교한다.
       부리가 긴 도요·물떼새류에서 특히. 예: 큰뒷부리도요 사진 약 1.5배인데 그림 2.1–2.5배.
     - **나는 모습의 보는 방향**: 보이는 면(머리의 정수리와 멱, 등과 배, 날개 윗면과 아랫면)이 모두 한 방향(위 또는 아래)에서 본 것인지,
       두 날개가 어깨에 붙어 있는지. 예: 세가락갈매기 도판에서 회색 등과 두 날개 윗면에 아래에서 본 흰 배가 함께 보였다. 슴새 도해에서 아래에서 본 흰 몸에 위에서 본 줄무늬 정수리가 붙었다.
     - **날개 방향**: 두 날개가 어깨에서 양옆으로 뻗었는지(머리 쪽으로 뻗거나 V자로 들리지 않았는지), 칼새·제비갈매기처럼 손목에서 꺾이는 종은 꺾였는지.
3. 떨어진 그림:
   - 그 webp 를 지운다(새로 추가된 것이면 삭제, 이미 커밋돼 있던 것을 덮어쓴 것이면 `git restore` 로 되돌림).
   - `art/review/<id>.txt` (동정 도해는 `<id>.id.txt`)에 무엇이 틀렸는지 영어 한 문장을 쓴다. Codex가 다시 그릴 때 프롬프트 끝에 붙인다.
4. `uv run tools/build.py` 로 `data/*/book.json` 과 링크 미리보기(`index.html` 의 share 칸, `aves/`, `og/`)를 다시 만든다.
5. 통과한 webp, `data/*/book.json`, 링크 미리보기(`git add index.html aves og` — 지워진 배너도 함께)만 스테이징해 커밋하고 `git push origin main`.
   - `ART_LOG.md` 는 pre-commit 훅이 스테이징된 그림으로 다시 만들어 커밋에 넣는다. 훅이 없으면 그림을 모두 스테이징한 **뒤에** `uv run tools/art_log.py` 를 실행하고 `ART_LOG.md` 를 스테이징한다.
   - 메시지는 이전 커밋 말투를 따른다: `삽화 추가: 동고비, 되지빠귀 · 붉은머리오목눈이 도판`.
   - 다른 파일(코드·종 자료·README)은 스테이징하지 않는다. 그런 변경이 있으면 건드리지 말고 보고에만 적는다.
   - 푸시가 실패하면(원격이 앞섬) `git pull --rebase` 후 한 번 더. 그래도 안 되면 멈추고 보고한다.
6. 짧게 보고한다: 올린 종, 떨어뜨린 종과 이유.

## 하지 말 것

- 그림을 직접 그리거나 고치지 않는다.
- `data/` 종 자료, 코드, `tools/style.toml`, 이 지침들을 고치지 않는다.
- `--force` 푸시, 다른 브랜치 만들기 금지.
